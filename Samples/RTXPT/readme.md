# RTXPT

RTXPT is a staged DiligentEngine port of NVIDIA RTXPT.

The first runnable version is a capability and fallback-view sample. Ray tracing, scene resources, shaders and post-processing are restored incrementally.

## Embedding the reference renderer

Include `cmake/RTXPTLibrary.cmake` to build the scene and embedded renderer without configuring the interactive sample, fetching assets, or requiring NRD/NGX. Both the sample and external hosts use its source list:

```cmake
include(path/to/RTXPT/cmake/RTXPTLibrary.cmake)
add_rtxpt_library(MyRTXPT NO_UI PATH_TRACING_ONLY DEPENDENCIES MyDiligentSDK)
target_link_libraries(MyHost PRIVATE MyRTXPT)
rtxpt_stage_shaders(MyHost "$<TARGET_FILE_DIR:MyHost>/shaders/rtxpt")
rtxpt_install_shaders("shaders/rtxpt")
```

`MyDiligentSDK` supplies Diligent include directories, link directories/libraries and platform definitions, using source targets or an installed SDK interface target. Installed shared archiver builds also require `DILIGENT_ARCHIVER_SHARED=1` on the library. `PATH_TRACING_ONLY` propagates to consumers because it affects public class layouts. `NO_UI` excludes ImGui calls. Neither option changes the reference tracing algorithm. Hosts enabling SHARC additionally provide `SHARC_SHADER_DIR` and deploy its includes. Reconstruction hosts may use `rtxpt_deploy_reconstruction_runtimes`; it reuses Core's enabled provider deployment helpers. Call it for the executable performing GPU work, including a separate render server when applicable.

`RTXPTEmbeddedScene` shares scene preparation across views. Each `RTXPTEmbeddedView` takes texture-local `RenderSize` and `DisplaySize`. Reference currently requires equal nonzero sizes and `DisplayRTVFormat = TEX_FORMAT_RGBA8_UNORM_SRGB`; unsupported requests return an explicit error. Host viewport origins belong only to final composition. Resize by reinitializing/replacing a view after its previous GPU use has completed; it starts fresh history and leaves the shared scene intact.

`GetOutput()` still returns the allocated display target, including before rendering for command recording. It is not proof of a successful frame. After checking `Render`, use `GetOutputInfo` for `Display`, `NoisyRadiance`, or `AccumulatedRadiance`. The descriptors identify texture size, resource/SRV formats, encoding, successful frame index and validity. Failed rendering invalidates all results; recovery resets reference accumulation. Failed reinitialization invalidates old targets. Descriptors and textures are borrowed until the next render/reinitialization/destruction; deferred work must hold its own resource references and obey GPU ordering.

Noisy radiance is current-frame linear RGBA16F; reference accumulation is linear RGBA32F. Display uses an sRGB RTV to encode once and a UNORM SRV to copy encoded bytes. `RTXPTPostProcessPipeline` independently takes an explicit tone-mapping RTV format and does not require a swapchain. The full interactive sample still includes its existing reconstruction dependencies.

## Shared realtime pipeline (RealtimeRaw and RealtimeNative)

NRD frame time is converted from renderer seconds to SDK milliseconds at the adapter
boundary. `LayerHistoryConfidence` is the current path assessment in **previous-frame
coordinates**: Prepare clears coverage, reprojects each path to NRD's bilinear footprint,
then resolves it with rejection winning conflicts and unmapped texels set to zero.
It is not a current-pixel validity mask. See [NRD input contracts](tests/NRD_INPUT_CONTRACTS.md).

`RTXPTEmbeddedView::Render` accepts optional per-frame `RTXPTViewDisplaySettings`: a linear display exposure multiplier (default 1, range [2^-32, 2^32]), the tone mapping operator (default Reinhard) with its white points, and Bloom (default off). The exposure changes the tone mapper's exposure compensation without rescaling HDR or resetting reference accumulation. Bloom is the Sample's `RTXPTBloomPass` on the display-size HDR before tone mapping, in every mode: `RTXPTDisplayBloom` copies the final HDR of the mode bit-exactly into a per-view RGBA16F target, downscales it twice, blurs it with sigma `clamp(Radius / 4, 1, 100)` and mixes `(1 - Intensity) * HDR + Intensity * blurred` there, so the published noisy, denoised, upscaled, reconstructed and accumulated HDR stay unchanged and `BloomRadiance` exports the result. Disabled Bloom or a zero radius or intensity runs no Bloom work and allocates nothing; the target, the pass and its intermediates are created by the first frame that draws Bloom and kept for the view. Out-of-range or non-finite settings (radius [0, 64], intensity [0, 0.1]) invalidate the frame output and return `InvalidArgument`; a failed Bloom setup or pass returns `BloomSetupFailed` or `BloomFailed`. None of these settings restarts history.

Auto exposure (`RTXPTViewDisplaySettings::AutoExposure`, default off) replaces the exposure multiplier with one the GPU adapts for each view, without CPU readback. The host keeps one `RTXPTAutoExposure` per camera and passes it to `Render`. Each frame first writes the exposure it uses, `2^clamp(b + CompensationEV, MinEV, MaxEV)`, from the committed base `b` or from `SeedEV` after `RequestSeed` (new view, new scene, camera cut, manual to auto). Tone mapping and DLSS RR's explicit exposure read that 1x1 R32F texture, and NGX auto exposure stays off. The mode's HDR before Bloom is then metered: the mean log2 luminance (0.299, 0.587, 0.114) of the finite pixels, with black and negative luminance at 1e-4. The meter writes a pending base adapted towards `log2(Key) - mean` by `1 - exp(-dt / tau)`, where tau is `BrightenSeconds` or `DarkenSeconds`, 0 reaches the target at once, and dt is capped at 1 s. The host calls `Commit` once it has accepted the whole frame, and a failed `Render` aborts it, so only accepted frames advance the state and its clock. The realtime clamps use the fixed reference `RTXPTTraceClampExposure` (1), whatever the manual or adapted exposure. Realtime captures export `auto_exposure_used` and `auto_exposure_next` (layout in `shaders/PostProcessing/RTXPTAutoExposureShared.h`). Invalid parameters fail the frame even in manual exposure; a failed setup or meter returns `AutoExposureSetupFailed` or `AutoExposureFailed`.

`RTXPTViewPostProcess` is that display tail on its own, for hosts that render their own scene-linear HDR, such as a rasterizer: auto exposure (metering the HDR before Bloom), Bloom and tone mapping, encoded once through an sRGB RTV. Embedded views run the same instance type after their mode, so a host's HDR and a view's displayed with the same settings, Bloom and auto exposure state give the same bytes. The HDR must be a display-size `kRTXPTDisplayHDRFormat` (RGBA16F) texture; `CreateRTXPTDisplayTarget` creates the display target the views use (RGBA8 typeless, sRGB RTV, UNORM default SRV). `Render` validates the settings, begins the auto exposure frame at the given time and aborts it when the frame fails; the host still commits it once it accepts the frame. `Apply` runs the passes alone, for callers that begin the auto exposure frame themselves.

Set `RTXPTEmbeddedViewCreateInfo::Mode = RTXPTViewMode::RealtimeRaw` to use the same `RTXPTRealtimePipeline` as the Sample's `--realtime_raw true` validation preset. Both use one sample per pixel, equal render/display sizes, an ordered graphics context, and manual exposure. Raw does not allocate progressive radiance history or run NRD, TAA, SR, RR, SHARC, or auto exposure (Bloom only when its display settings request it), and does not need NRD; the core library links NRD only when it is built with `NRD_TARGET`, and never NGX.

The pipeline runs BuildDenoisingLayers, current light-buffer/feedback preparation, FillDenoisingLayers, current-frame guide baking, no-denoiser final merge, then the existing tone mapper. Layer radiance guides explicitly skip history reads. The view host owns scene preparation, ray bindings and light sampling, and supplies its frame constants; the common pipeline uploads those constants and owns layer/guide/merge targets. Raw hosts configure Uniform or Power+ sampling, so NEE-AT history is not consumed. Per-view frame/mini constants are bound to SRBs rather than shared cached PSO static variables.

After successful rendering, `GetOutputInfo` also exposes `RayDistance`, `PrimaryMotion`, `SpecularHitDistance`, `AverageLayerRadiance` and `LayerHeader`. `GetRealtimeLayerBuffer()` exposes the corresponding packed layer surface/material records. RayDistance is the tracer's scene ray distance, **not view-space Z**. `GetRealtimeStats().DynamicMotionValidated` is true: primary motion of direct rigid/skinned surfaces and the separate specular motion of single rigid planar reflections are numerically tested. Paths without a supported correspondence (refraction, multiple delta bounces, non-planar mirrors) report invalid history instead of approximate motion while the camera or any surface along them moves or changes material; when nothing along such a path changed since the previous frame it reprojects onto itself with zero motion and keeps valid history. Untracked or reset instances and missed rays are always invalid. They are still not a validated NRD/SR/RR input set; each reconstructor must map them to its own contract. Failure invalidates color and guides together; `AccumulatedRadiance` is unavailable in Raw. Completion counters advance only after the full chain succeeds.

The Sample preset freezes rendering controls and disables its settings UI for validation; normal camera input and requested scene animation still work. It disables Vulkan RR capability requests and rejects combinations with embedded reference or advanced validation presets. Its existing advanced realtime route remains available when `--realtime_raw` is omitted. For four separate current-frame HDR captures, run from the Sample source directory with an absolute output path:

```text
RTXPT.exe --mode d3d12 --scene convergence-test.scene.json --width 320 --height 240 --realtime_raw true --show_ui false --hdr_capture_path <absolute-output-prefix> --hdr_capture_start 2 --hdr_capture_count 4 --hdr_capture_sequence true --exit_after_frames 10
```

Each capture is a single frame. Capture readbacks wait for the GPU only when requested; the regular Raw frame has no CPU wait. Scene loading support is unchanged: the standalone Sample can animate its imported scenes, while `RTXPTEmbeddedScene` retains its existing initial static-import restriction. Dynamic runtime instances can still be prepared through the shared scene runtime; correct dynamic motion remains separate work.

`RTXPTViewMode::RealtimeNative` (Sample: `--realtime_native true`, exclusive with `--realtime_raw`) runs the same chain and denoises each of the three layers with its own NRD RELAX instance (`RTXPTNrdDenoiser`) before the merge; the result is linear HDR in `DenoisedRadiance`, tone-mapped once into `Display`. It needs a library built with NRD (otherwise initialization returns `DenoiserUnavailable`) and compute plus UAV support for every denoiser format (`DenoiserUnsupportedDevice`). Tracing and preparation use the Sample's realtime defaults: Power+ NEE, firefly filter 0.10 converted with the pre-exposure, radiance clamp 8, primary indirect specular suppression 0.6, three layers and maximum vertex depth 9. The first frame, a host cut, missed frames, a failed or revoked frame and reinitialization (mode or size change) restart every layer (`CLEAR_AND_RESTART`); otherwise the history continues and prepare writes each layer's history confidence (`LayerHistoryConfidence`, R8_UNORM, selected with the `Layer` argument of `GetOutputInfo`), which is 0 where the layer path has no valid previous correspondence, so RELAX uses only the current frame there. `RTXPTEmbeddedViewCreateInfo::NativeHistoryConfidence = false` disables that input for validation. `GetRealtimeStats()` reports denoise dispatches, history resets, NRD instances and pool bytes; GPU timing covers prepare, NRD and merge in one `NRD` stage. Each view owns its NRD instances.

```text
python tests/capture_realtime_baseline.py --exe <RTXPT.exe> --output <new-directory> --preset native --repeats 3
```
